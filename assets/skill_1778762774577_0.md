# Code Downloader - Git/SVN 代码下载技能

## 何时使用

当用户提供 Git 或 SVN 仓库地址，并希望将代码下载到本地时使用此技能。技能会自动判断仓库类型，管理下载配置，让用户确认命令后再执行。

**重要：此技能仅限于下载公司内部项目代码。在开始任何操作前，必须先询问用户确认。**

## 工作流程概述

0. 询问用户是否用于公司内部项目——若不是则中止
1. 解析用户提供的 URL，判断是 Git 还是 SVN
2. 加载配置文件 `~/.claude/code-downloader-config.json`，检查必需配置项（首次使用或缺少配置时引导用户配置）
3. 从 URL 提取仓库名，根据路径模板计算目标目录
4. 确定要执行的命令（clone/checkout 或 pull/update）
5. 展示命令，让用户确认后执行
6. 保存配置，返回下载结果

---

## 第一步：确认使用范围

在使用本技能执行任何操作前（包括 URL 识别、配置检查等），**必须先询问用户**：

> 用 AskUserQuestion 询问："即将使用 Code Downloader 下载代码，这是否为公司内部项目的代码？"
> - 选项 1："是，继续下载" → 继续执行后续流程
> - 选项 2："否，取消" → 回复"已取消下载操作"并中止技能

**仅当用户选择"是"时才继续后续步骤，否则立即中止。**

---

## 第二步：URL 识别

判断用户提供的地址是 Git 还是 SVN：

**判断为 Git 的条件（任一满足即可）：**
- URL 包含 `github.com`、`gitlab.com`、`bitbucket.org`、`gitee.com`
- URL 以 `git@` 开头（SSH 格式）
- URL 以 `.git` 结尾
- URL 包含 `.git`

**判断为 SVN 的条件（任一满足即可）：**
- URL 路径中包含 `/svn/` 或 `/svn`
- URL 包含 `/trunk`、`/branches/`、`/tags/`
- URL 包含 `/branch/`（单数形式，SVN 常见路径模式，如 `baseline/branch/jiande`）
- URL 以 `svn://` 或 `svn+ssh://` 开头

**模糊情况处理：**
如果上述规则无法确定（例如自建 Git 服务器且 URL 不带 `.git`），则：
1. 优先尝试 `git ls-remote <url>` - 如果成功则为 Git
2. 如果失败，尝试 `svn info <url>` - 如果成功则为 SVN
3. 如果两者都失败，用 AskUserQuestion 询问用户"这个地址是 Git 仓库还是 SVN 仓库？"

---

## 第三步：配置管理

配置文件路径：`~/.claude/code-downloader-config.json`

**配置格式：**
```json
{
  "git_root": "D:/projects/git",
  "git_default_branch": "main",
  "git_path_template": "{root}/{repo_name}/PC/{repo_name}_debug",
  "svn_root": "D:/projects/svn",
  "svn_path_template": "{root}/{repo_name}"
}
```

**模板变量：**
- `{root}` → `git_root` 或 `svn_root` 的值
- `{repo_name}` → 从 URL 中提取的仓库名

### 加载配置

用 Read 工具读取 `~/.claude/code-downloader-config.json`。如果文件不存在或读取失败，视为空配置 `{}`。

### 检查并补充配置（以 Git 为例，SVN 同理）

逐一检查配置项，缺失时用 AskUserQuestion 询问用户，提供合理的默认值，**一次只问一个问题**，得到回答后再继续下一个：

1. **检查 `git_root`** — 如果缺失：
   - 问题："Git 仓库的根目录是？所有 Git 项目将下载到此目录下的子目录中。"
   - 默认值：`D:/projects/git`
   - 用户输入后将其存储到配置对象中

2. **检查 `git_default_branch`** — 如果缺失：
   - 问题："Git 仓库的默认分支名是什么？"
   - 默认值：`main`
   - 用户输入后将其存储到配置对象中

3. **检查 `git_path_template`** — 如果缺失：
   - 问题："Git 项目下载的路径模板是什么？（支持 {root} 和 {repo_name} 变量）"
   - 默认值：`{root}/{repo_name}/PC/{repo_name}_debug`
   - 用户输入后将其存储到配置对象中

> **SVN 配置同理**，检查 `svn_root`（默认 `D:/projects/svn`）和 `svn_path_template`（默认 `{root}/{repo_name}`），不需要默认分支。

> **特殊入口**：如果用户在 prompt 中说"修改配置"或"重新配置"，则重置对应类型的所有配置项（清除 git_root / git_default_branch / git_path_template / svn_root / svn_path_template 中对应的类型），让流程重新询问。

## 第四步：提取仓库名

从 URL 中提取仓库名称。**公司内部 GitLab URL 采用 `nis_<项目名>` 的命名规范**，项目名所在段的前一段通常为 `nis_projects`。需要特殊处理。

### 提取优先级

**规则 1（优先）— 匹配 `nis_` 前缀段：**
在 URL 路径中查找以 `nis_` 开头的路径段（如 `nis_zunyinew`）：
1. 取该段中 `nis_` 之后的部分（`zunyinew`）
2. 将首字母转为大写（`Zunyinew`）
3. 这就是仓库名

**规则 2（SVN 分支路径）— 匹配 `/branch/` 段：**
如果 URL 路径中包含 `/branch/`（SVN 分支路径模式），提取分支名作为仓库名：
1. 在 URL 路径中定位 `/branch/` 之后紧跟的路径段（如 `jiande`）
2. 将该段首字母转为大写（`Jiande`）
3. 这就是仓库名
4. 注意：要匹配的是路径中的单个 `/branch/` 段，不要与 `/branches/` 混淆，先精确匹配 `/branch/`（前后有分隔符）

**规则 3（回退）— 取最后一段：**
如果 URL 中没有 `nis_` 前缀段也没有 `/branch/` 段，则使用原有规则：
1. 去掉末尾的 `.git`
2. 取 URL 路径的最后一段
3. 去掉尾随的 `/`

### 示例

- `http://192.168.160.149/zhyl/hlywzx/nis_projects/nis_zunyinew/PC.git`
  → 匹配 `nis_zunyinew` → 提取 `zunyinew` → 首字母大写 → **`Zunyinew`**
- `https://github.com/user/my-repo.git` → 无 `nis_` 段 → 取最后一段 → **`my-repo`**
- `git@github.com:user/my-repo.git` → **`my-repo`**
- `https://svn.example.com/svn/my-project/trunk` → **`my-project`**
- `https://192.168.10.141/mcsd/EwellNISProject/baseline/branch/jiande/EMC/PC`
  → 匹配 `/branch/jiande` → 提取 `jiande` → 首字母大写 → **`Jiande`**

### 首字母大写规则

使用 Bash 命令进行首字母大写转换（兼容 Bash 4+）：
```bash
# 例如 name="zunyinew" → "Zunyinew"
name="$(tr '[:lower:]' '[:upper:]' <<<"${name:0:1}")${name:1}"
```

## 第五步：计算目标路径

将路径模板中的变量替换为实际值：

- `{root}` → 对应的根目录（如 `D:/projects/git`）
- `{repo_name}` → 上一步提取的仓库名

示例：
- 模板 `{root}/{repo_name}/PC/{repo_name}_debug` + URL `http://192.168.160.149/zhyl/hlywzx/nis_projects/nis_zunyinew/PC.git`
  → 仓库名 `Zunyinew` → `D:/Work/Git/Zunyinew/PC/Zunyinew_debug`
- 模板 `{root}/{repo_name}` + URL `https://github.com/user/my-repo.git`
  → 仓库名 `my-repo` → `D:/projects/git/my-repo`

注意：路径使用 Windows 风格正斜杠（`D:/projects/...`），Bash 工具可以正确处理。

---

## 第六步：Git 下载流程

1. 检查 prompt 中是否指定了分支（用户说了"拉取 develop 分支"等）。如果有，使用用户指定的分支；否则使用配置中的 `git_default_branch`
2. 检查目标目录是否存在（`ls -d <目标路径> 2>/dev/null`）：
   - **目录已存在**：进入目录执行 `git pull`（确保当前在正确的分支上）
     - 命令：`cd <目标路径> && git pull`
   - **目录不存在**：先 `mkdir -p <父目录>`，然后 `git clone`
     - 命令：`mkdir -p <父目录(不含仓库名最后一级)> && git clone -b <branch> <url> <目标路径>`
3. **执行前确认**：用 AskUserQuestion 展示将要执行的命令，询问用户是否确认执行
   - 标题：确认执行
   - 选项：确认执行 / 取消
   - **在 `question` 文本中直接包含完整命令**（不要依赖 `preview` 字段，因为用户不一定会看到）
4. 用户确认后，用 Bash 工具执行命令
5. **配置有变更时才保存**：只有在前面的步骤中确实修改了配置（新增/修改配置项）时，才用 Write 工具写入 `~/.claude/code-downloader-config.json`。如果配置与读取时一致无任何变化，则跳过写操作
6. 返回下载结果和最终路径给用户

---

## 第七步：SVN 下载流程

1. **检查 SVN CLI 是否可用**：`which svn 2>/dev/null || svn --version 2>/dev/null`
   - 如果不可用 → AskUserQuestion："SVN 命令行工具未安装，是否要安装？"
     - 选项：安装 SVN CLI / 取消
     - 如果选择安装：尝试 `winget install Slik.Subversion --accept-package-agreements`（安装完成后将 SlikSvn bin 目录加入 PATH），安装后继续
     - 如果选择取消：中止操作并告知用户需要安装 SVN CLI

2. 检查目标目录是否存在（`ls -d <目标路径> 2>/dev/null`）：
   - **目录已存在**：`svn update <目标路径>`
   - **目录不存在**：`mkdir -p <父目录> && svn checkout <url> <目标路径>`

3. **执行前确认**：用 AskUserQuestion 展示将要执行的命令，询问用户是否确认执行
   - 标题：确认执行
   - 选项：确认执行 / 取消
   - **在 `question` 文本中直接包含完整命令**（不要依赖 `preview` 字段）

4. 用户确认后执行命令
5. **配置有变更时才保存**：只有配置确实发生变更时才写入，无变更则跳过
6. 返回下载结果和路径

---

## 重要注意事项

- **配置文件有变更时才保存**：在展示命令给用户确认之前，如果配置项有新增或修改则写文件，确保下次使用时新配置生效。如果所有配置项已存在且值未变，则跳过写操作
- **一次只问一个问题**：在 AskUserQuestion 中一次只问一个问题。如果需要配置多个项，逐个询问，得到回答后再问下一个
- **命令优先使用简洁形式**：对于 `git clone`，不需要 `--progress` 等冗余参数；保持命令简洁清晰
- **路径中的空格**：如果路径包含空格，在 Bash 命令中要用引号包裹
- **目标目录已存在但非仓库**：如果 `git pull` 失败（目录存在但不是 git 仓库），告知用户并建议手动处理
- **优先匹配 `nis_` 前缀**：URL 路径中优先查找 `nis_` 开头的段来提取项目名。如果 URL 符合 `.../nis_projects/nis_<name>/...` 模式，则仓库名为首字母大写的 `<name>`，而不是 URL 最后一段
- **SVN 分支路径匹配次优先**：如果没有 `nis_` 前缀，检查 URL 是否包含 `/branch/` 路径段（如 `.../baseline/branch/jiande/...`），提取分支名作为仓库名。注意区分单数 `/branch/` 和复数 `/branches/`
